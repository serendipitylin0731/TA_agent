# 系统架构

```mermaid
flowchart LR
  A[维护者本地同步脚本] --> B[教材 PDF]
  B --> C[分页 Markdown 与关键插图]
  C --> D[(SQLite 教材库与 FTS5)]
  U[用户] --> S[教材检索]
  U --> Q[Chat 问答]
  U --> R[原版教材阅读]
  S --> D
  Q --> D
  D --> M[模型组织回答]
  Q -->|检索未命中| M
  M --> U
  R --> B
```

教材库只存储教材。同步脚本从既定来源下载 PDF，批量转换脚本把每页可提取文字和部分嵌入插图生成 Markdown，再用分页正文重建检索索引。原始 PDF 页序与学段、学科、册次始终保留。普通用户只有查询与阅读权限；Web API 没有上传、删除或网页导入端点。仅有图像而无文字层的扫描页仍需 OCR 才能检索图中文字。

检索把转换后的分页正文做 NFKC 归一化并消除跨行空白，保存一份 FTS5 索引；原文仍保留，供片段和页码展示。搜索时拆出主题与“定义、过程、顶点式、发展”等限定词，再按主题命中、限定词距离、正文位置和章节上下文排序。章节标题只提供少量加权，因为它可能作为页眉反复出现。目录页、前言和练习题中的干扰片段会降低权重，主题词散落在同页但未构成完整概念时不作为强证据。错别字建议来自实际教材词表。

跨章节问题会扩展主题检索，并从不同书页选取证据，供模型综合。引用标记指向具体 PDF 页；无合适教材匹配，或模型判断检索片段不足以回答时，改用模型回答，在答案下方单独提示未命中，不伪造引用。查询原文按书合并多个命中页。

前端使用本地 KaTeX 渲染数学公式，用本地 PDF.js 把教材页面绘制成双页画布，不嵌入浏览器 PDF 工具栏。从搜索或引用进入时打开命中页；从目录进入时打开第一页。下一命中按钮通过页级索引定位。封面由 PDF 首页在服务端生成并缓存。返回按钮会回到原页面；左侧分别显示最近 10 个聊天会话和 10 次检索记录，保存在浏览器本地。点击导航中的 Chat 或查询原文会开启空白页面。API Key 只在服务端环境变量中读取。

主要只读 API：`GET /api/status`、`GET /api/catalog`、`GET /api/sources`、`GET /api/sources/{id}/content`、`GET /api/sources/{id}/file`、`GET /api/sources/{id}/markdown`、`GET /api/sources/{id}/markdown-images/{name}`、`GET /api/sources/{id}/cover`、`GET /api/sources/{id}/pages`、`POST /api/search`、`GET /api/suggest`、`POST /api/chat`。POST 均是查询请求，不修改知识库。
